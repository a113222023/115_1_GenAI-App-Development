# Week 11｜RAG 文件問答系統測試紀錄

## 一、作業說明

本次作業沿用原本的 RAG App，並使用自行撰寫的虛構文件進行測試。

- 文件名稱：`校園讀書交流活動企劃.txt`
- 文件類型：自行撰寫的虛構測試資料
- 文件內容：活動日期、地點、活動內容、報名方式及注意事項
- 執行方式：使用原本的 Streamlit RAG App

## 二、執行模式與模型版本

- 執行模式：真實 API
- Embedding 模型：`text-embedding-3-small`
- 回答模型：`gpt-5.4-mini`
- 文件切割方式：空白行分段
- 原始 Top K：2
- 重測 Top K：5
- Min Score：0.2

## 三、測試問題與結果

| 測試類型 | 問題 | 測試結果 |
|---|---|---|
| 正常問題 | 活動預計在哪一天舉辦？ | 第一次未找到日期段落，調整 Top K 後成功回答 2026 年 12 月 15 日 |
| 資訊不足 | 這次活動邀請了哪一位講師？ | 文件沒有講師資訊，系統正確回答無法確認 |
| 文件外 | 台灣最高的山是哪一座？ | 文件沒有相關資料，系統正確回答無法確認 |

## 四、日期與引用核對

原始文件記載活動日期為 2026 年 12 月 15 日。

調整 Top K 為 5 後，系統成功找到正確段落，回答：

「活動預計於2026年12月15日舉辦。[來源3]」

經過人工核對，回答日期與原文一致，引用來源也正確。

## 五、錯誤修正與重測

- 預期結果：系統應找到活動日期並正確回答。
- 實際結果：第一次 Top K 設為 2，檢索結果沒有包含日期段落。
- 修正方式：將 Top K 從 2 調整為 5。
- 重測結果：成功找到包含日期的段落，並正確回答 2026 年 12 月 15 日。

## 六、API 請求次數

- 執行模式：真實 API
- 原始測試：3 題
- 額外重測：1 次
- 總測試次數：4 次

API 實際請求次數請依 App 的使用紀錄或 API 計數填寫，不將 Session 累計數字直接當成單次測試請求數。

## 七、尚未測試項目

1. 尚未測試大型文件的檢索效果。
2. 尚未測試多份文件同時檢索。
3. 尚未測試大量使用時的系統穩定性。
4. 尚未測試不同 Embedding 模型的檢索效果。

## 八、RAG 系統限制與心得

自行建置 RAG 系統雖然可以根據文件回答問題，但回答品質會受到文件內容與檢索結果影響。如果檢索不到正確的段落，即使文件中有答案，AI 也可能回答無法確認。調整 Top K 可以增加找到相關資料的機會，但也可能帶入不相關的內容。另外，RAG 無法保證所有引用都正確，因此仍然需要人工核對原文。若文件本身沒有提供資訊，系統也不應自行編造答案。
